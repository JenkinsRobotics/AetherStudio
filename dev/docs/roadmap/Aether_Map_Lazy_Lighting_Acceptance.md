## Independent surface scheduling — proposed 2026-10-04

Jonathan clarified that reusing an asset on several surfaces does not imply
simultaneous playback. Current format-4 Visual owns one interval and several
targets: Repeat/Span share playback and settings. That is **not independent
per-surface scheduling**; this remains unimplemented.

Recommended authoring model: Assets lists reusable sources once; timeline clips
reference those sources and own start/duration/source offset and target(s).
A surface-oriented timeline shows each scene and its surfaces as rows, with
asset clips positioned by time. Simultaneous multi-surface uses appear as linked
clips across target rows, with one shared clock and Repeat/Span mapping; a later
use is a separate clip referencing the same source. The scene itself also has a
row. A single Assets-oriented summary can remain available for managing sources.
The surface tray edits the currently selected use's targets, while the timeline
edits when it plays. Clicking a source in Assets should not silently retime all
uses or imply that all assignments are simultaneous.

Before implementation, specify legacy migration, linked versus independent clip
selection/editing, overlap/layer order, source-clock behavior and consistent
editor/output rendering. Existing files must keep their appearance and timing.
No schema or independent-scheduling capability is shipped by the tray interaction
change. The supplied Lazy Lighting guide describes scenes/timeline with parameter
automation; it does not establish all of these proposed scheduling semantics.


## Media pool foundation and compound timeline direction — 2026-10-05

The reusable-source step is now implemented: format 5 stores pool assets separately
from scheduled visual clips. Each drop creates a clip referring to the source;
source overrides, timing, effects and targets can differ between uses. Surface
and scene tabs project visual tracks; sequential clips can share a track and
additional tracks layer them. The scene tab currently shows all tracks. It is
**not yet the nested master timeline** described below. Audio soundtrack tracks,
clip-local spatial composition transforms, and compound timeline instances remain
unimplemented. Existing Repeat/Span clips still work across multiple targets.

Jonathan's refinement: a named compound timeline groups several mapped surfaces
and appears as ONE layer/clip in the Scene timeline. It has the same internal
visual/audio-track editing experience as a surface timeline. Grouping references
surface identities; it never merges or rewrites their geometry, masks or warp.
A Media Pool source remains independent of any of these timelines.

Next model step:
- Composition definitions own internal tracks; scheduled composition instances
  in the Scene timeline own start, duration, source offset/loop and master layer
  order. Surface and compound compositions use the same representation.
- A compound owns explicit surface membership and Repeat/Span sampling. Repeat
  maps the complete composition to each face. Span samples one shared window
  through the union of the faces. Unfolded UV wrapping remains a distinct feature.
- The master composes each instance as a unit, so moving it above/below another
  moves all its internal tracks together. Internal clip settings remain local.
- Audio routes once per scheduled instance even when its picture targets several
  faces. Nested timing needs an explicit scene-to-local clock mapping.
- Master rows support trim/move/duplicate/mute/lock; opening a row reveals its
  internal timeline tab. Flat composition preview supports content placement;
  mapped preview continues to show the projector result.
- Reusing the same surface in a compound and an individual composition is
  explicit layering. Creating a compound must not silently delete/hide existing
  work. Reject cyclic references if composition nesting is exposed.

Acceptance must include source reuse at different times, three-face compound
Span/Repeat, independent geometry edits, nested clock/trim/loop behavior, master
and internal ordering, single audio routing, undo, old-show visual equivalence,
save/reload and matching physical-output/export rendering. A filtered track view
alone does not satisfy this nested-composition feature.

## Main timeline modes refinement — 2026-10-05

Jonathan's latest direction is a single Main timeline: create tracks, place pool
assets, then assign visual clips to surfaces with the existing picker. Standard
keeps simple asset rows; Advanced exposes video/audio tracks. This supersedes
the preceding per-surface tab editing UI for now, without implementing or
removing the proposed future compound representation. The Main modes and audio
